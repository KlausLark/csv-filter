# 4. Техническое решение и архитектура

## 4.1. Выбранный технологический стек

| Компонент | Решение | Обоснование |
|---|---|---|
| Язык | Python 3 | Подходит для учебной разработки и обработки табличных данных |
| Графический интерфейс | Tkinter / ttk | Позволяет создать настольное окно без обязательной сторонней GUI-библиотеки |
| Чтение и запись CSV | Стандартный модуль csv | Не требует отдельной зависимости для базовых CSV-операций |
| Файловые диалоги | tkinter.filedialog | Привычный способ выбора файлов |
| Автоматизированные тесты | unittest | Стандартное средство тестирования Python |
| Контроль версий | Git | Хранение истории изменений и возврат к предыдущим версиям |
| Публикация документации | GitHub | Удобный просмотр Markdown по ссылке |

Выбор ориентирован на небольшой локальный инструмент. Сервер, база данных, API Gateway и микросервисы не нужны: приложение не обслуживает удалённых пользователей и не хранит общую базу данных.

## 4.2. Логическая структура приложения

Приложение делится на четыре логические части:

1. **Интерфейс:** открытие файла, выбор параметров фильтрации, показ таблицы и запуск экспорта.
2. **Чтение CSV:** открытие файла, получение заголовков и строк, обработка ошибок кодировки и формата.
3. **Модуль фильтрации:** применение выбранного оператора к значениям выбранного столбца.
4. **Экспорт:** запись заголовков и отобранных строк в выбранный файл.

Разделение логики и интерфейса позволяет проверять фильтрацию отдельно от графических элементов.

## 4.3. Схема взаимодействия

```text
Пользователь
    |
    v
Графический интерфейс (Tkinter)
    |
    +--> Чтение CSV --> Исходные заголовки и строки
    |                         |
    |                         v
    +------------------> Модуль фильтрации
                              |
                              v
                       Результат фильтрации
                         |             |
                         v             v
                   Табличный просмотр  Экспорт CSV
                                             |
                                             v
                                      Новый файл
```

## 4.4. Поток обработки данных

1. Пользователь открывает CSV-файл.
2. Модуль чтения получает заголовки и строки.
3. Интерфейс отображает данные и разрешает выбрать столбец.
4. Пользователь задаёт оператор и значение.
5. Модуль фильтрации проверяет каждую строку и формирует список подходящих записей.
6. Интерфейс показывает результат и число совпадений.
7. При подтверждении пользователя модуль экспорта записывает результат в новый файл.

Исходный набор данных сохраняется отдельно от результата фильтрации, чтобы сброс условия не требовал повторного чтения файла.

## 4.5. Сторонние сервисы и интеграции

В MVP сторонние сервисы не требуются. Программа не использует внешние API, платёжные системы, почтовые шлюзы, карты, SMS или сетевую базу данных. Единственный вход и выход данных - файлы на компьютере пользователя.

Такое решение соответствует назначению утилиты, сокращает объём разработки и устраняет зависимость от доступности внешних провайдеров. При необходимости импорта данных из сторонних систем это будет отдельным изменением объёма проекта.

## 4.6. Обработка неоднозначных CSV

CSV не всегда имеет единый формат: разделителем могут быть запятая или точка с запятой, а кодировки могут отличаться. В MVP основная кодировка - UTF-8. При неоднозначности разделителя приложение должно позволять выбрать его явно.

При ошибке декодирования приложение показывает сообщение и не считает частично прочитанные данные корректно загруженными.

Для числового сравнения ячейка преобразуется в число. Если преобразование невозможно, строка не проходит числовое условие. Это правило должно одинаково применяться в программе и тестах.

## 4.7. Обоснование архитектурных решений

**Локальное приложение вместо веб-сервиса.** Это сокращает объём разработки и не требует размещения сервера.

**Стандартная библиотека вместо большого набора зависимостей.** Это упрощает установку и снижает риск проблем совместимости.

**Отдельный результат фильтрации.** Исходные данные остаются доступными, поэтому пользователь может сбросить фильтр и не рискует перезаписать оригинал.
