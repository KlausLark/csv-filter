# 3. Нефункциональные требования

Нефункциональные требования описывают качество работы приложения, его ограничения и правила обработки данных.

## 3.1. Производительность

- Для контрольного файла до 10 000 строк и 20 столбцов целевой ориентир загрузки и фильтрации - до 2 секунд на согласованном тестовом компьютере.
- При измерении фиксируются характеристики компьютера, размер файла и кодировка.
- Приложение избегает ненужных повторных проходов по одним и тем же данным.
- Значительно более крупные файлы могут потребовать потоковой обработки, что не входит в обязательный MVP.

Указанное время является целью для проверки, а не подтверждённой характеристикой до проведения измерений.

## 3.2. Надёжность

- Ошибки ввода-вывода должны обрабатываться исключениями.
- Исходный файл не должен изменяться при фильтрации и экспорте.
- Пустой файл, пустые ячейки и некорректные числовые значения не должны приводить к аварийному завершению.
- Экспорт считается успешным только после завершения записи.
- После ошибки пользователь может исправить проблему и повторить действие.

## 3.3. Удобство использования

- Основной сценарий выполняется через графический интерфейс.
- Названия действий и сообщения об ошибках должны быть на русском языке.
- Результат фильтрации должен быть виден до сохранения.
- Пользователь должен понимать, какой файл открыт и сколько строк найдено.
- Ошибки описываются понятным языком, без необходимости разбирать трассировку Python.

## 3.4. Совместимость и сопровождаемость

- Целевая среда первой версии - настольный компьютер с установленным Python 3.
- Tkinter и модуль csv уменьшают количество внешних зависимостей.
- Код разделяется на функции чтения, фильтрации, отображения и экспорта, чтобы упростить тестирование и развитие.
- Поддерживаемые версии Python и операционные системы фиксируются после фактического тестирования.
- После добавления исходного кода инструкция запуска размещается в README.

## 3.5. Безопасность и конфиденциальность

- Обработка выполняется локально; передача пользовательских файлов в интернет не предусмотрена.
- Программа не должна выполнять содержимое CSV как код.
- Имена файлов и значения ячеек рассматриваются как данные.
- При экспорте пользователь явно выбирает путь сохранения.
- Если в таблице присутствуют персональные или коммерческие сведения, пользователь отвечает за соблюдение правил их хранения и передачи.

## 3.6. Проверяемость

Для проверки требований подготавливаются контрольные файлы: корректный CSV, пустой файл, файл с пустыми ячейками, файл с нечисловыми значениями в числовом столбце и файл с альтернативным разделителем.
