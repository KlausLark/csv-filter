# 2. Функциональные требования и критерии приёмки

Каждая пользовательская история описывает ценность для пользователя. Критерии приёмки определяют, как проверить готовность функции.

## US-01. Загрузка CSV-файла

**История:** Как пользователь, я хочу выбрать CSV-файл на компьютере, чтобы просмотреть содержащиеся в нём данные.

**Критерии приёмки:**
1. По команде открытия отображается диалог выбора файла.
2. После успешного чтения заголовки и строки отображаются в таблице.
3. Если файл пустой, недоступен или не читается, программа показывает понятное сообщение.

**Приоритет:** Must have.

## US-02. Выбор условия фильтрации

**История:** Как пользователь, я хочу выбрать столбец, оператор и значение, чтобы указать, какие строки нужно оставить.

**Критерии приёмки:**
1. Список столбцов формируется из заголовков загруженного файла.
2. Пользователь может выбрать оператор и ввести значение.
3. Если обязательное значение не задано, программа не запускает фильтрацию и предлагает заполнить поле.

**Приоритет:** Must have.

## US-03. Фильтрация числовых значений

**История:** Как пользователь, я хочу отобрать строки, где числовое значение больше, меньше или равно заданному, чтобы находить нужные записи без ручного просмотра.

**Критерии приёмки:**
1. Для оператора «больше» остаются только строки, в которых значение столбца больше заданного числа.
2. Для операторов «меньше» и «равно» применяется соответствующее числовое сравнение.
3. Пустые и нечисловые значения не вызывают аварийного завершения и не проходят числовое условие.

**Приоритет:** Must have.

## US-04. Фильтрация текстовых значений

**История:** Как пользователь, я хочу искать строки по точному совпадению или наличию фрагмента текста, чтобы отбирать записи по названию или статусу.

**Критерии приёмки:**
1. Операторы «равно» и «не равно» сравнивают текстовые значения.
2. Оператор «содержит» находит строки, в которых выбранная ячейка включает введённый фрагмент.
3. Правило учёта регистра единообразно для всех текстовых сравнений и описано в интерфейсе или справке.

**Приоритет:** Must have.

## US-05. Просмотр результата и сброс фильтра

**История:** Как пользователь, я хочу увидеть отфильтрованные строки и количество совпадений, чтобы оценить результат до экспорта.

**Критерии приёмки:**
1. После применения фильтра таблица показывает только подходящие строки.
2. Интерфейс отображает количество найденных записей.
3. Сброс фильтра возвращает все исходные строки.

**Приоритет:** Must have.

## US-06. Экспорт результата

**История:** Как пользователь, я хочу сохранить отфильтрованные строки в новый CSV-файл, чтобы использовать результат отдельно от оригинала.

**Критерии приёмки:**
1. Пользователь может выбрать имя и расположение выходного файла.
2. Экспортированный файл содержит заголовки и только строки результата.
3. При ошибке записи показывается сообщение; исходный файл не изменяется.

**Приоритет:** Must have.

## US-07. Обработка ошибок

**История:** Как пользователь, я хочу получать понятные сообщения при проблемах с файлом, чтобы понимать, что исправить.

**Критерии приёмки:**
1. Ошибка чтения не приводит к аварийному закрытию программы.
2. Сообщение объясняет проблему на понятном языке и, если возможно, предлагает следующий шаг.
3. Программа не сообщает об успешном экспорте, если запись не завершилась.

**Приоритет:** Must have.

## US-08. Удобство интерфейса

**История:** Как пользователь, я хочу выполнять основные действия из одного окна, чтобы не изучать команды терминала.

**Критерии приёмки:**
1. Основные действия обозначены понятными кнопками или элементами управления.
2. До загрузки файла фильтрация и экспорт недоступны либо сопровождаются пояснением.
3. После выполнения действия интерфейс отображает актуальное состояние данных.

**Приоритет:** Should have.

## 2.1. Общие правила фильтрации

- За один раз применяется одно условие.
- Для числовых операторов значение условия должно быть числом.
- Пустые или нечисловые ячейки не проходят числовой фильтр.
- Правило учёта регистра для текстового поиска одинаково во всём приложении.
- Сброс фильтра возвращает исходный набор данных, а не результат предыдущей фильтрации.
- Фильтрация не изменяет исходный файл.
